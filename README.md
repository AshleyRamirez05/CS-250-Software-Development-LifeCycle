# CS 250 Software Development Lifecycle

## Sprint Review and Retrospective

This repository includes my Sprint Review and Retrospective from CS 250. Throughout this course, I learned about Agile and Scrum practices and how they can help software development teams communicate, manage requirements, and respond to changes.

### How do I interpret user needs and implement them into a program? How does creating user stories help with this?

I think understanding user needs starts with listening to what the customer wants and asking questions when something is unclear. User stories help break those needs into smaller features that developers can understand and work on. During the SNHU Travel project, we looked at customer requests such as destination listings and personalized vacation options. This helped me understand why requirements need to be clear before development begins.

### How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

When developing a program, I would start by understanding the requirements and planning how the features should work before writing code. I also think testing throughout development is important because it helps identify problems early. In the future, I would like to use Agile practices such as Sprint Planning, regular team communication, and Sprint Reviews. These processes can help keep development organized while allowing changes when necessary.

### What does it mean to be a good team member in software development?

I believe being a good team member means communicating clearly, being responsible for your work, and helping others when problems come up. Software development requires collaboration because different team members may be working on different parts of the same project. From the SNHU Travel activities, I learned that sharing updates, asking questions, and being open to feedback can help a team stay focused on completing its goals.
